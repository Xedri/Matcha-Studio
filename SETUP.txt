MATCHA STUDIO — SUPABASE TEST VERSION

1. Use a dedicated new Supabase Free project. In the SQL Editor, create a new query and paste the entire contents of setup.sql. Run it once. If an error occurs, stop and read the error; do not rerun blindly against an existing database.
2. Under Authentication > Users, create an administrator account with your own email and a strong unique password. Copy its User UID. In a new SQL query, paste promote-admin.sql, replace both placeholders with that exact UID, then run. Verify the result shows role=admin.
3. Create a separate customer account through Authentication > Users for testing. Newly created accounts have role=customer by default. Never share passwords or secret/service_role keys.
4. Start a local web server in the extracted website directory, for example using the existing VS Code Live Server workflow. Open index.html via the server URL instead of double-clicking the file. Keep the existing Video/matcha-promo.mp4 in the project if available.
5. In Supabase Authentication URL Configuration, set your test site URL and allow the exact login.html redirect URL if using self-registration with confirmation. The free tier's default email service may be restricted; owner-created users are a useful first test. Do not disable confirmation for a public site merely to make signup easier.
6. Confirm the 8 catalog items load. Sign in as the customer and place a fictional test order; view My Account > My Orders. Submit a fictional event inquiry. Sign out, sign in as the private administrator, confirm both records appear, and change an order status or product availability. Sign back in as the customer to verify the change.
7. Test that a customer cannot read another customer's order or modify catalog/status data and an unauthenticated visitor can read only public products/categories. Database rules, not the frontend, enforce permissions. Do not publish real customer data without a separate production security and privacy review.

The project URL and publishable key are configured in supabase-config.js. This key is meant for browser use; secrets and service-role keys must stay private. The website uses the official Supabase JavaScript library over the internet.

Do not replace your existing live portfolio demo yet. Test this new version locally first on the Free plan. No real payments are implemented. Orders and booking notes are stored in Supabase; use fictional details for all testing. The existing GitHub Pages demo can remain public while you test the database version separately.

Before commercial use, use appropriate hosting, review permissions and privacy, provide backups, monitor quotas, replace third-party imagery with licensed assets, and verify the full order workflow.
